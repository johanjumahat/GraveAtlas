# GraveAtlas Search

## Overview

GraveAtlas provides unified search across cemeteries, graves, and people. Search is deterministic (no AI), server-side, and supports full Unicode.

## API

```
GET /api/search?q=<query>&type=<type>&limit=<n>&offset=<n>
```

| Parameter | Default | Max | Description |
|-----------|---------|-----|-------------|
| `q` | required | — | Search query (min 2 characters) |
| `type` | `all` | — | Filter: `all`, `cemetery`, `grave` |
| `limit` | 100 | 500 | Results per page |
| `offset` | 0 | — | Pagination offset |

## Search Ranking

Results are scored and sorted by relevance:

| Match Type | Score | Description |
|------------|-------|-------------|
| Exact match | 100 | Query exactly equals target |
| Normalized exact | 90 | Match after accent/diacritic removal |
| Alt name exact | 85 | Match against alternative names |
| Prefix match | 70 | Target starts with query |
| Alt name prefix | 65 | Alt name starts with query |
| Partial match | 50 | Target contains query |
| Alt name partial | 45 | Alt name contains query |
| City match | 30 | City name contains query |
| Country match | 25 | Country name contains query |

Higher scores rank first. Ties are broken alphabetically.

## Unicode Support

Search handles all Unicode scripts:
- Arabic (مقبرة)
- Chinese (安祥园)
- Japanese (青山霊園)
- Korean (국립묘지)
- Cyrillic (кладбище)
- Greek (κοιμητήριο)
- Hebrew (בית קברות)
- Devanagari (कब्रिस्तान)
- Thai (สุสาน)
- Malay (kubur)
- Indonesian (pemakaman)
- Accented Latin (café → cafe)

Normalization: NFD decomposition + diacritic removal for normalized matching. Original characters are always preserved in stored data.

## Alternative Names

Records can have:
- `name` — Primary display name
- `localName` — Name in original script/language
- `transliteration` — Romanized version
- `altNames` — Array of alternative names

Search checks all of these.

## Performance

- **Debouncing**: Android client debounces search input (300ms delay)
- **Min query length**: 2 characters
- **Max results**: 50 per search request
- **Pagination**: All results paginated
- **Caching**: Search results cached locally for 2 minutes
- **No keystroke API calls**: Client never sends a request per keystroke

## Scalability Notes

Current search reads files from the GitHub data repository per request. This works for small-to-medium datasets (hundreds to low thousands of records).

### Future Scalability Requirements (not yet implemented)

For larger datasets (10,000+ records), consider:
- Pre-built search index (generated by GitHub Actions, stored in `index/`)
- Cloudflare Durable Objects for in-memory search cache
- Dedicated search service (Phase 5+)

No paid search engine is used. No AI is used for basic search.
